# Офлайн-блокнот

У Анны и Бориса есть заметка с одним ключом `route`. Каждый видит свой текст.
Оба пользуются одной справкой и одним хранилищем. Хранилище работает в памяти,
поэтому сценарий можно повторить на месте.

## Запуск

Из корня workspace выполните

```sh
dart pub get
dart run managed/example/managed_example.dart
```

В журнале `+` означает создание экземпляра, `−` — завершение его очистки.
Номер после `#` закреплён за объектом на весь запуск. Проследите за
`NoteEditor#6` при обновлении профиля и сбросе кэша. [Сценарий](managed_example.dart)

## Как устроен граф

Стрелка ведёт от потребителя к регистрации из его `dependsOn`. Чтобы
посмотреть фактическое дерево до создания экземпляров, выполните из корня
workspace `dart run managed/example/managed_example.dart --graph`.
Пример читает `dependencies`, `managedType` и `scope` у самих регистраций.
Знак ↩ отмечает повторное обращение к уже показанной регистрации.

```mermaid
flowchart LR
  editor["NoteEditor · singleton"] --> repo["Notebook / CachedNotebook · cached"]
  editor --> buffer["DraftBuffer · unique"]
  repo --> user["User · source"]
  repo --> storage["NoteStorage · singleton"]
  repo --> cache["Личный TextCache · cached"]
  cache --> user
  cache --> storage
  exportNote["Экспорт в Markdown · unique"] --> repo
  exportNote --> user
  exportNote --> template["MarkdownTemplate · unique"]
  template --> style["MarkdownStyle · cached"]
  template --> heading["MarkdownHeading · unique"]
  help["TextCache справки · cached"]
```

- `AppModule.helpCache` и `NotesModule.cache` используют фабрику
  `TextCache.new`. У справки список входов пуст. Личные заметки зависят
  от пользователя и хранилища. Поэтому logout очищает личный кэш, а справка
  остаётся доступной. Прямой вызов `Scope.cached.provideUsing(TextCache.new)`
  возвращает тот же кэш, что и `AppModule.helpCache()`.
- `NotesModule.repository.as<Notebook>()` позволяет редактору и экспорту
  запрашивать интерфейс через `Manage.resolve<Notebook>()`. Обе регистрации
  ведут к одному репозиторию. Функция `showRoute` принимает `Provider<Notebook>`
  и при каждом чтении получает блокнот текущего пользователя.
- `EditorModule.editor` получает собственный `unique`-буфер. Пока редактор
  доступен из кэша своего `singleton`-скоупа, повторное обращение возвращает
  его вместе с тем же буфером. Для отдельного буфера, взятого через
  `EditorModule.buffer()` вне графа, `close()` вызывает владелец.

Фабрики и обработчики жизненного цикла собраны в глобальных модулях.
Сами классы блокнота принимают обычные аргументы конструктора. [Регистрации](lib/registrations.dart) · [Модель блокнота](lib/notebook.dart)

## Что происходит при смене сессии

1. До входа доступна справка. Попытка открыть редактор доходит до пустого
   `AuthModule.user` и завершается с `StateError`.
2. Анна сохраняет заметку и получает обновлённый профиль. `sameIdentity`
   сравнивает `id`, поэтому `user()` отдаёт новую фамилию, а редактор сохраняет
   свой номер. В поле `repository.owner` виден снимок, переданный конструктору.
   По умолчанию источники сравнивают значения через `identical`.
3. Анна редактирует время поезда и вызывает `await Scope.cached.reset()`.
   `onDispose` редактора записывает черновик через ещё открытый репозиторий.
   Затем освобождаются буфер, репозиторий и кэши. Новый редактор читает
   сохранённое время. У источника та же сессия, у хранилища тот же номер.
4. При прямом переключении на Бориса последняя правка записывается на аккаунт
   Анны. Борис открывает тот же ключ и видит пустую заметку. Обработчик
   `onDispose` источника получает последний профиль Анны после её сервисов.
5. Борис оставляет черновик, выходит через `await AuthModule.user.clear()`
   и входит снова с тем же объектом `User`. Он получает новый редактор и
   читает свой текст из хранилища.

## Экспорт и генерация кода

Для сохранённой заметки параметры одного экспорта выглядят так

```dart
final markdown = await ExportModule.markdown(
  ExportNoteParams('route', title: 'План поездки', includeAuthor: false),
);
```

`ExportNoteParams.inject` передаёт ключ через `ZoneValues` и вызывает
сгенерированный провайдер шаблона с вложенными `MarkdownHeadingParams`.
Пользователя и блокнот подставляет `dependsOn`. Заголовок и подпись задаются
для каждого экспорта. Общий стиль задаёт `MarkdownStyleProvider.params` при
создании кэшированного экземпляра. Поэтому смена префикса с `##` на `#`
видна после `Scope.cached.reset()`.

В репозиторий включён результат генерации, так что обычный запуск сразу
показывает работающий экспорт. При изменении `@ManagedType` пересоберите
провайдеры из каталога `managed/example`. [Классы с аннотациями](lib/markdown.dart) · [Сгенерированные Params и провайдеры](lib/module.dart)

```sh
dart run build_runner build --delete-conflicting-outputs
```

## Подмена хранилища и незавершённые операции

Из каталога `managed/example` запустите `dart test`. В тестах
`AppModule.storage.mock(fake)` меняет хранилище у уже открытого редактора,
а `resetMock()` возвращает исходную регистрацию. Черновик старого редактора
записывается в то хранилище, из которого был открыт блокнот.

Два теста управляют моментом завершения ввода-вывода через `Completer`.
Один переключает пользователя во время чтения и проверяет, что отложенный
`Manage.resolve<User>()` отклоняет экспорт из завершённой сессии. Другой
совмещает logout со сбросом кэша во время записи. Запись вызывается один раз,
оба ожидающих получают ошибку хранилища, а остальные ресурсы освобождаются.
[Тесты блокнота](test/notebook_test.dart)
